# Задание 1. Анализ и планирование

Чтобы составить документ с описанием текущей архитектуры приложения, можно часть информации взять из описания компании условия задания. Это нормально.

### 1. Описание функциональности монолитного приложения

**Управление отоплением:**

- Пользователи могут включать/выключать отопление
- Система поддерживает
  - включение/отключение отопления
  - получение информации об установленном модуле отопления
  - изменение информации об установленном модуле отопления
- Система не поддерживает добавление нового модуля отопления через web-интерфейс

**Мониторинг температуры:**

- Пользователи могут устанавливать нужную температуру, получать информацию о текущей температуре
- Система поддерживает:
  - установку нужной температуры
  - получение информации о текущей температуре
- Система получает данные о температуре с датчиков, судя по тому, что есть сущность TemperatureSensor и репозиторий TemperatureSensorRepository

### 2. Анализ архитектуры монолитного приложения

Перечислите здесь основные особенности текущего приложения: какой язык программирования используется, какая база данных, как организовано взаимодействие между компонентами и так далее.
**Особенности текущего приложения**
- Язык программирования: Java
- База данных: PostgreSQL
- Архитектура: Монолитная, все компоненты системы (обработка запросов, бизнес-логика, работа с данными) находятся в рамках одного приложения.
- Взаимодействие: Синхронное, запросы обрабатываются последовательно.
- Масштабируемость: Ограничена, так как монолит сложно масштабировать по частям.
- Развёртывание: Требует остановки всего приложения.

### 3. Определение доменов и границы контекстов

Опишите здесь домены, которые вы выделили.

Основные домены:
- отопление
  - управление отоплением (включение/выключение температуры)
- мониторинг температуры
  - получение температуры с датчиков в домах

### **4. Проблемы монолитного решения**

- добавление новой функциональности, приводит к сложности поддержка решения, из-за его большого размера
- время релиза и деплоя в прод увеличивается
- риск ошибок повышается
- сложность в масштабировании отдельных компонентов
- увеличение конфликтов в коде при разработке нескольких задач параллельно
